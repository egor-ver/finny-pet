# Питомец Финни

Мобильное приложение для Android — игровой сервис, который формирует базовые
финансовые навыки у детей 7–11 лет.

Ребёнок заводит виртуального питомца, получает игровую валюту за задания и
периодический доход, до начала игрового периода распределяет её минимум по трём
направлениям — обязательные расходы, необязательные расходы и накопления, — а
затем видит, как принятые решения отражаются на состоянии и развитии питомца.

Реальные деньги, банковские счета, платежи, реклама и сбор персональных данных в
решении не используются. Вся валюта внутриигровая и не имеет реальной стоимости.

Разработано по техническому заданию №6 Департамента финансов города Москвы.

## Статус

**Игровая логика готова, идёт сборка экранов.**

Полностью сделаны доменный слой с экономикой, хранилище и дизайн-система.
Из экранов работают знакомство с игрой, создание питомца, главный экран,
план личного бюджета, магазин, копилка и задания: приложение заводит профиль,
открывает игровой день, начисляет доход, даёт распределить монеты по трём
направлениям, после подтверждения продаёт товары со списанием и влиянием на
питомца, объясняет отказ при нехватке денег, даёт выбрать цель, откладывать и
брать из копилки с превью срока, проводит через задания трёх видов с наградой
за одно в день и показывает, как план сходится с тратами. Профиль переживает
закрытие приложения — при следующем запуске игра открывается на главном.

Следующий шаг — закрытие дня и итоги.

**Тесты:** 411 юнит-тестов и 143 инструментальных, все проходят.

Матрица соответствия обязательным требованиям — в разделе
[Реализация требований](#реализация-требований).

## Быстрый запуск

Требуется Android SDK с установленной платформой **android-37.1** и JDK 21.
Отдельно ставить JDK не обязательно: Gradle подтянет нужный toolchain сам
(`gradle/gradle-daemon-jvm.properties`), либо подойдёт JBR из комплекта
Android Studio.

Сборка из терминала самодостаточна и IDE не требует. Для работы в Android
Studio нужна версия **2026.1.1 или новее**: более ранние не поддерживают
AGP 9.2.1 и откажутся синхронизировать проект.

Клонировать и собрать debug-сборку:

```bash
git clone https://github.com/egor-ver/finny-pet.git
cd finny-pet
./gradlew :app:assembleDebug
```

APK окажется в `app/build/outputs/apk/debug/app-debug.apk`.

Прогнать юнит-тесты — домен, экономика, разбор контента:

```bash
./gradlew :app:testDebugUnitTest
```

Прогнать тесты на устройстве или эмуляторе — хранилище, экраны, доступность:

```bash
./gradlew :app:connectedDebugAndroidTest
```

Установить на подключённое устройство:

```bash
./gradlew :app:installDebug
```

Файл `local.properties` не хранится в репозитории — Android Studio создаёт его
при первом открытии проекта. Если собираешь из терминала без IDE, укажи путь к
SDK вручную или через переменную окружения `ANDROID_HOME`.

## Архитектура

Четыре слоя со строго однонаправленным потоком данных:

```
┌─────────────────────────────────────────────────────────────┐
│                    UI (Jetpack Compose)                     │
│             отрисовка состояния, ничего больше              │
└──────────────────────────────┬──────────────────────────────┘
                               │  действия ↓ · состояние ↑
┌──────────────────────────────┴──────────────────────────────┐
│                          ViewModel                          │
│                 собирает состояние экрана,                  │
│                  о Room и ассетах не знает                  │
└──────────────────────────────┬──────────────────────────────┘
                               │  команды ↓ · модели ↑
┌──────────────────────────────┴──────────────────────────────┐
│                   Domain (чистый Kotlin)                    │
│           модели, движки экономики, правила игры            │
└──────────────────────────────┬──────────────────────────────┘
                               │  запросы ↓ · модели ↑
┌──────────────────────────────┴──────────────────────────────┐
│                     Data (репозитории)                      │
│          фасад над двумя независимыми источниками           │
└──────────────┬───────────────────────────────┬──────────────┘
               │                               │
 ┌─────────────┴─────────────┐   ┌─────────────┴─────────────┐
 │ Room (SQLite)             │   │ assets / JSON             │
 │                           │   │                           │
 │ изменяемое состояние:     │   │ неизменяемый контент:     │
 │ профиль, периоды,         │   │ задания, товары, цели,    │
 │ операции, прогресс        │   │ тексты, числа экономики   │
 └───────────────────────────┘   └───────────────────────────┘
```

- **UI** — только отрисовка состояния и передача действий пользователя.
  Функция отрисовки отделена от экрана с зависимостями, поэтому каждый экран
  тестируется на произвольном состоянии, без графа Hilt.
- **ViewModel** — собирает `StateFlow` состояния экрана и обрабатывает
  действия. Про Room и ассеты не знает. Разовые события — переход после
  сохранения, показ ошибки — не вызываются напрямую, а попадают в состояние
  фактом: экран видит флаг и реагирует. Иначе переход, начатый в корутине,
  терялся бы при повороте.
- **Domain** — чистый Kotlin без единого импорта androidx: модели, движки
  экономики, сценарии. Здесь же основная масса тестов.
- **Data** — репозитории поверх двух независимых источников.

Ключевое разделение — **два источника данных**. Состояние игрока меняется и
живёт в Room; учебный контент только читается из JSON-файлов в ассетах. Это
выполняет требование ТЗ 3.2 об отделении учебного контента от интерфейсного кода
и позволяет добавлять новые задания без правок в коде (ТЗ 2.5.14).

Миграций пока нет: до первого релиза при смене схемы база пересоздаётся.
Это осознанное решение на время разработки — правки в структуре данных идут
часто, и поддерживать миграции между промежуточными версиями дороже, чем
завести профиль заново.

### Минимальный объём демонстрационного контента (ТЗ 2.6)

| Элемент | Минимум | Сейчас |
|---|---|---|
| Стадии развития питомца | 3 | **3** |
| Комбинации внешности питомца | 9 | 8 |
| Позиции для покупки | 8 | 2 |
| Цели накопления | 3 | 1 |
| Задания по 3 темам | 6 | 1 |
| Игровые периоды | 5 | сходимость экономики за 5 периодов проверена тестом; воспроизведение в приложении ждёт демонстрационного режима |

Комбинация внешности — это сочетание, которое ребёнок выбирает при создании
питомца: тело, окрас и аксессуар; стадии роста за варианты не считаются
(подтверждено ментором). Сейчас один вид, четыре окраса и один аксессуар —
`4 × (1 + 1) = 8`, все двенадцать картинок шарфа на месте. Ещё два аксессуара
рисуются, с ними будет 16.

## Особенности сборки

**`android.disallowKotlinSourceSets=false`.** В AGP 9 включена встроенная
поддержка Kotlin, которая запрещает регистрировать исходники через
`kotlin.sourceSets`. KSP всё ещё пользуется этим DSL для сгенерированного кода,
поэтому guard снят штатным флагом. Убрать, когда KSP перейдёт на
`android.sourceSets`.

**`compileSdk = 37.1` при `targetSdk = 36`.** Шесть зависимостей androidx
требуют компиляции против API 37. Поднятие `compileSdk` открывает новые API, но
не меняет рантайм-поведение приложения — для этого поднимают `targetSdk`, и это
отдельное решение.

## Границы проекта

Согласно ТЗ 2.7 в решении намеренно отсутствуют:

- подключение реальных банковских счетов, карт, СБП и государственных систем;
- операции с реальными деньгами, платные подписки, внутриигровые покупки,
  реклама и вознаграждения с реальной стоимостью;
- публичные чаты между детьми, рейтинги с персональными данными, социальная сеть;
- полноценный удалённый родительский контроль и отдельный веб-кабинет.
