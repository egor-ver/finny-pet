# Питомец Финни

Мобильное приложение для Android — игровой сервис, который формирует базовые
финансовые навыки у детей 7–11 лет.

Ребёнок заводит виртуального питомца, получает игровую валюту за задания и
периодический доход, до начала игрового периода распределяет её минимум по трём
направлениям — обязательные расходы, необязательные расходы и накопления, — а
затем видит, как принятые решения отражаются на состоянии и развитии питомца.

Реальные деньги, банковские счета, платежи, реклама и сбор персональных данных в
решении не используются. Вся валюта внутриигровая и не имеет реальной стоимости.

Разработано по техническому заданию №6 Департамента финансов города Москвы.

## Статус

**Каркас проекта.** Настроены сборка, внедрение зависимостей, хранилище и
структура модулей. Игровая логика и экраны ещё не реализованы — приложение
запускается на заглушечный экран.

Матрица соответствия обязательным требованиям — в разделе
[Реализация требований](#реализация-требований).

## Быстрый запуск

Требуется Android SDK с установленной платформой **android-37.1** и JDK 21.
Отдельно ставить JDK не обязательно: Gradle подтянет нужный toolchain сам
(`gradle/gradle-daemon-jvm.properties`), либо подойдёт JBR из комплекта
Android Studio.

Клонировать и собрать debug-сборку:

```bash
git clone https://github.com/egor-ver/finny-pet.git
cd finny-pet
./gradlew :app:assembleDebug
```

APK окажется в `app/build/outputs/apk/debug/app-debug.apk`.

Прогнать юнит-тесты:

```bash
./gradlew :app:testDebugUnitTest
```

Установить на подключённое устройство:

```bash
./gradlew :app:installDebug
```

Файл `local.properties` не хранится в репозитории — Android Studio создаёт его
при первом открытии проекта. Если собираешь из терминала без IDE, укажи путь к
SDK вручную или через переменную окружения `ANDROID_HOME`.

## Архитектура

Четыре слоя со строго однонаправленным потоком данных:

```
┌─────────────────────────────────────────────────────────────┐
│                   UI (Jetpack Compose)                      │
│            • Только отрисовка StateFlow<UiState>            │
└──────────────────────────────┬──────────────────────────────┘
           │ UiEvent           ▲ StateFlow<UiState>
           ▼                   │ SingleLiveEvent / Channel
┌──────────────────────────────┴──────────────────────────────┐
│                         ViewModel                           │
│        • onEvent(UiEvent)    • Ничего не знает о Data       │
└──────────────────────────────┬──────────────────────────────┘
           │ Вызовы Use Case   ▲ Flow<DomainModel>
           ▼                   │
┌──────────────────────────────┴──────────────────────────────┐
│                    Domain (Pure Kotlin)                     │
│  • Модели экономики  • Бизнес-правила  • JVM Unit-тесты     │
└──────────────────────────────┬──────────────────────────────┘
           │ Запросы / Команды ▲ Domain Entities
           ▼                   │
┌──────────────────────────────┴──────────────────────────────┐
│                     Data (Repositories)                     │
│          • Фасад над двумя независимыми источниками         │
└──────────────────────┬───────────────────────┬──────────────┘
                       │                       │
                       ▼                       ▼
    ┌──────────────────────────────┐ ┌──────────────────────────────┐
    │     Room (SQLite DB)         │ │        assets / JSON         │
    │  • Мутабельное состояние     │ │  • Неизменяемый контент      │
    │  • Баланс, цели, прогресс    │ │  • Каталог квестов и покупок │
    │  • app/schemas для миграций  │ │  • ТЗ 3.2 (изоляция от UI)   │
    └──────────────────────────────┘ └──────────────────────────────┘

```

- **UI** — только отрисовка `UiState` и отправка `UiEvent`, без бизнес-логики.
- **ViewModel** — `StateFlow<UiState>`, `onEvent(UiEvent)`, одноразовые эффекты
  через `Channel`. Не знает ни про Room, ни про ассеты.
- **Domain** — чистый Kotlin без зависимостей от Android: модели и движки
  экономики. Здесь же сосредоточены юнит-тесты.
- **Data** — репозитории поверх двух независимых источников.

Ключевое разделение — **два источника данных**. Состояние игрока меняется и
живёт в Room; учебный контент только читается из JSON-файлов в ассетах. Это
выполняет требование ТЗ 3.2 об отделении учебного контента от интерфейсного кода
и позволяет добавлять новые задания без правок в коде (ТЗ 2.5.14).

Схемы базы выгружаются в `app/schemas` и коммитятся — без них нельзя написать
тест миграции.

## Особенности сборки

**`android.disallowKotlinSourceSets=false`.** В AGP 9 включена встроенная
поддержка Kotlin, которая запрещает регистрировать исходники через
`kotlin.sourceSets`. KSP всё ещё пользуется этим DSL для сгенерированного кода,
поэтому guard снят штатным флагом. Убрать, когда KSP перейдёт на
`android.sourceSets`.

**`compileSdk = 37.1` при `targetSdk = 36`.** Шесть зависимостей androidx
требуют компиляции против API 37. Поднятие `compileSdk` открывает новые API, но
не меняет рантайм-поведение приложения — для этого поднимают `targetSdk`, и это
отдельное решение.

## Границы проекта

Согласно ТЗ 2.7 в решении намеренно отсутствуют:

- подключение реальных банковских счетов, карт, СБП и государственных систем;
- операции с реальными деньгами, платные подписки, внутриигровые покупки,
  реклама и вознаграждения с реальной стоимостью;
- публичные чаты между детьми, рейтинги с персональными данными, социальная сеть;
- полноценный удалённый родительский контроль и отдельный веб-кабинет.
