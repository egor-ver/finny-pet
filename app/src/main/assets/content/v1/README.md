# Контент-пак v1

Здесь живёт весь учебный контент: числа экономики, внешность питомца, товары,
цели, задания, словарь и тексты. Код эти файлы только читает.

**Правила на все файлы:**

- Кодировка UTF-8, формат JSON. Комментарии внутри JSON запрещены — пояснения тут.
- Все `id` — латиницей, без пробелов: `food-porridge`, `plan-pocket-money`.
- Все `id` уникальны внутри своего файла.
- Поля, которые кончаются на `Key` — это **ключи текстов**, а не сами тексты.
  Сам текст пишется в `explanations.json` под этим ключом.
- Заполненные записи в файлах — **примеры**. Их можно править и удалять.
- Приложение проверяет минимумы при запуске и падает с понятным сообщением,
  если контента меньше нормы. Это сделано нарочно: лучше поймать на своём
  устройстве, чем на защите.

## balance.json — числа экономики

Одиннадцать чисел, на которых держится вся игра.

| Поле | Что это |
|---|---|
| `startingBalance` | сколько монет у ребёнка в самом начале |
| `periodIncome` | сколько начисляется в начале каждого игрового периода |
| `taskReward` | ориентир награды за задание (у каждого исхода своя, эта — базовая) |
| `initialStat` | стартовые настроение, сытость и уход, от 0 до 100 |
| `statPenaltyMissedMandatory` | насколько падают сытость и уход, если обязательное не оплачено |
| `moodBonusPlanFollowed` | насколько растёт настроение, если план выполнен |
| `growthForMandatoryCovered` | очки роста за покрытые обязательные расходы |
| `growthForPlanFollowed` | очки роста за выполненный план целиком |
| `growthForSavingsKept` | очки роста за выполненный план по накоплениям |
| `growthThresholds` | три порога стадий развития, первый обязательно `0`, дальше строго по возрастанию |
| `carryOverUnspent` | переносится ли неистраченное на следующий период: `true` или `false` |

**Обязательная проверка.** За 5 периодов разумной игры питомец должен дойти до
последней стадии. ТЗ 2.6 требует показать 5 периодов и 3 стадии — если арка не
укладывается, на защите мы покажем детёныша.

Формула: `(growthForMandatoryCovered + growthForPlanFollowed + growthForSavingsKept) × 5`
должно быть не меньше последнего числа в `growthThresholds`.

Проверить на текущих числах: `(2 + 2 + 1) × 5 = 25`, последний порог `25`. Сходится.

**Вторая проверка.** Самая дорогая цель должна собираться примерно за 4–5
периодов, если ребёнок откладывает разумную долю. Не за один и не за двадцать.

## pets.json — внешность питомца

Три списка: тела, окрасы, аксессуары. Внешность — это их сочетание.

**Минимум по ТЗ 2.6 — не менее 9 визуально различимых комбинаций.**
Комбинаций получается `тела × окрасы × (аксессуары + 1)`; плюс один, потому что
вариант «без аксессуара» приложение добавляет само.

Примеры, дающие 9 и больше:

- 3 тела × 3 окраса, аксессуаров нет → 9
- 2 тела × 2 окраса × (2 аксессуара + без) → 12
- 1 тело × 3 окраса × (2 аксессуара + без) → 9

**От тебя нужны ещё и картинки**: PNG с прозрачным фоном, имя файла совпадает
с `id`. Это самая долгая позиция во всём контенте — начни с неё.

## shop.json — товары

**Минимум по ТЗ 2.6 — не менее 8 позиций, оба типа обязательно.**

| Поле | Что это |
|---|---|
| `price` | цена в монетах, больше нуля |
| `category` | `MANDATORY` — обязательный расход, `OPTIONAL` — желаемый |
| `effects` | как покупка влияет на питомца, список |

В `effects` каждый пункт — это `stat` и `delta`:

- `stat`: `MOOD` (настроение), `SATIETY` (сытость), `CARE` (уход)
- `delta`: на сколько меняется, от −100 до 100, но **не ноль**

Смысл разделения: `MANDATORY` — то, без чего питомцу плохо (еда, уход).
`OPTIONAL` — то, что радует, но без чего можно обойтись (игрушки, украшения).
Отказ от необязательной покупки по ТЗ прямо назван нормой, а не ошибкой.

## goals.json — цели накопления

**Минимум по ТЗ 2.6 — не менее 3 целей.**

Цель — предмет или событие с понятной ребёнку ценой. `price` больше нуля.
Хорошо, когда цели разной стоимости: одна близкая, одна средняя, одна дальняя.

## tasks.json — задания

**Минимум по ТЗ 2.6 — не менее 6 заданий, по трём темам.**

`topic` — одно из трёх, и все три должны быть представлены:

- `PLANNING` — планирование бюджета
- `SAVING` — формирование сбережений
- `PAYMENTS` — платежи и покупки

**Задание — это игровая ситуация с выбором и последствиями**, а не тест с
вариантами ответа. Так прямо сказано в ТЗ 2.5.8.

### Шаги: три вида

**`CHOICE` — выбор из вариантов.** Нужно не менее двух вариантов.

```
{
  "type": "CHOICE",
  "promptKey": "task.my_task.step1",
  "options": [
    { "id": "buy_now", "labelKey": "task.my_task.opt_buy" },
    { "id": "wait", "labelKey": "task.my_task.opt_wait" }
  ]
}
```

**`DISTRIBUTE` — разложить сумму по трём направлениям.**

```
{ "type": "DISTRIBUTE", "promptKey": "task.my_task.step1", "budget": 40 }
```

**`PICK_ITEMS` — собрать корзину в рамках бюджета.** `itemIds` берутся из `shop.json`.

```
{
  "type": "PICK_ITEMS",
  "promptKey": "task.my_task.step1",
  "itemIds": ["food-porridge", "toy-ball"],
  "budget": 30
}
```

### Исходы

**У каждого задания не меньше двух исходов, и ровно один из них — `OTHERWISE`.**
`OTHERWISE` срабатывает, когда не подошёл ни один другой. Без него задание не
загрузится.

`condition` бывает четырёх видов:

| Вид | Когда срабатывает |
|---|---|
| `{"type": "OPTION_CHOSEN", "optionId": "wait"}` | ребёнок выбрал этот вариант |
| `{"type": "SAVED_AT_LEAST", "amount": 10}` | отложил не меньше указанного |
| `{"type": "SPENT_AT_MOST", "amount": 30}` | потратил не больше указанного |
| `{"type": "OTHERWISE"}` | во всех остальных случаях |

`reward` — награда в монетах, можно `0`. `effects` — как у товаров, необязательное поле.

**Объяснение обязательно у каждого исхода, включая неудачный.** ТЗ 2.5.8 требует
короткое объяснение независимо от правильности решения, а ТЗ 2.5.9 — чтобы
неудачный исход объяснял последствие и подсказывал, как поправить.

## glossary.json — словарь терминов

Справочный раздел из ТЗ 2.5.11. Термин — это `titleKey` (само слово) и
`bodyKey` (объяснение в одну-две короткие фразы).

Кандидаты: бюджет, план, накопления, цель, обязательные расходы, желаемое.

## explanations.json — тексты

Плоский список: ключ и текст. Сюда идут **все** `...Key` из остальных файлов
плюс системные ключи, которые приложение показывает само.

Системные ключи уже перечислены в файле — их набор фиксированный, он приходит
из кода, добавлять и удалять их нельзя. Тексты в них менять нужно.

**Подстановки.** Фигурные скобки заменяются числами на лету:

| Ключ | Что подставляется |
|---|---|
| `purchase.done` | `{price}`, `{balance}` |
| `purchase.rejected` | `{shortfall}`, `{price}` |
| `balance.credited` | `{amount}`, `{source}` |
| `savings.deposited`, `savings.goal_reached`, `savings.withdrawn` | `{amount}`, `{saved}`, `{remaining}` |
| `growth.points_added`, `growth.stage_up` | `{earned}`, `{points}` |
| исходы заданий | `{reward}`, `{balance}` |

Ключи `recovery.*` — это подписи на кнопках, которые приложение предлагает,
когда денег не хватило. Их пять, набор тоже фиксированный.

## Требования к текстам

Всё это напрямую из ТЗ, раздел 3.6 и 2.2:

- Возраст читателя — 7–11 лет. Короткие фразы, простые слова.
- Сложный термин либо не используется, либо тут же объясняется.
- **Не пугать, не стыдить.** Питомец не болеет и не умирает от ошибок ребёнка.
  Неудача — это временная задача, а не наказание.
- Ошибка объясняется вместе со способом её исправить.
- Никаких упоминаний реальных денег, банков, брендов и финансовых продуктов.
