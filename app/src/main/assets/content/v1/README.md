# Контент-пак v1

Здесь живёт весь учебный контент: числа экономики, внешность питомца, товары,
цели, задания, словарь и тексты. Код эти файлы только читает.

**Правила на все файлы:**

- Кодировка UTF-8, формат JSON. Комментарии внутри JSON запрещены — пояснения тут.
- Все `id` — латиницей, без пробелов: `food-porridge`, `plan-pocket-money`.
- Все `id` уникальны внутри своего файла.
- Поля, которые кончаются на `Key` — это **ключи текстов**, а не сами тексты.
  Сам текст пишется в `explanations.json` под этим ключом.
- Заполненные записи в файлах — **примеры**. Их можно править и удалять.
- Приложение проверяет минимумы при запуске и падает с понятным сообщением,
  если контента меньше нормы. Это сделано нарочно: лучше поймать на своём
  устройстве, чем на защите.

## balance.json — числа экономики

Восемнадцать чисел, на которых держится вся игра.

| Поле | Что это |
|---|---|
| `startingBalance` | сколько монет у ребёнка в самом начале |
| `periodIncome` | сколько начисляется в начале каждого игрового периода |
| `taskReward` | ориентир награды за задание (у каждого исхода своя, эта — базовая) |
| `initialStat` | стартовые настроение, сытость и уход, от 0 до 100 |
| `nightDropSatiety`, `nightDropCare`, `nightDropMood` | насколько за ночь, при закрытии игрового дня, падают сытость, уход и настроение; не меньше нуля |
| `statFloor` | ниже этого значения ночь показатель не опускает, от 0 до 100; если показатель уже ниже, ночь его не трогает |
| `needThreshold` | сытость или уход ниже этого значения — потребность дня, от 0 до 100. Нужное выполнено, когда потребностей нет, сколько бы ни было потрачено |
| `sadThreshold` | сытость или уход ниже этого значения — сова грустит, и заданием дня становится разбор ошибки. От 0 до 100 |
| `needSlack` | на сколько план на нужное может превышать цену потребностей, прежде чем сова скажет «мне столько не нужно» |
| `growthForMandatoryCovered` | сколько очков роста стоит звезда «Сыт» — потребности закрыты. В день, когда потребности не закрыты, звёзд нет совсем |
| `growthForPlanFollowed` | звезда «По плану» — нужного и желаемого потрачено не больше отдельных сумм плана; экономия допустима |
| `growthForSavingsKept` | звезда «Отложил» — копилка пополнена по плану, и план копилки больше нуля |
| `growthThresholds` | три порога стадий развития, первый обязательно `0`, дальше строго по возрастанию |
| `carryOverUnspent` | переносится ли неистраченное на следующий период: `true` или `false` |
| `rewardedTasksPerPeriod` | сколько заданий в игровой день приносят монеты; остальные играются ради объяснения и питомца. Ноль — задания без монет вовсе |
| `parentBonus` | сколько монет взрослый начисляет ребёнку за дело вне игры (ТЗ 2.5.12). Начислить можно раз в игровой день, больше нуля |

**Обязательная проверка.** За 5 периодов питомец должен дойти до последней
стадии, даже если один день из пяти прошёл с ошибкой: демо показывает именно
такой день. ТЗ 2.6 требует показать 5 периодов и 3 стадии — если арка не
укладывается, на защите мы покажем детёныша.

Формула: `(growthForMandatoryCovered + growthForPlanFollowed + growthForSavingsKept) × 4`
должно быть не меньше последнего числа в `growthThresholds`.

Проверить на текущих числах: `(1 + 1 + 1) × 4 = 12`, последний порог `10`. Сходится.

**Вторая проверка.** Самая дешёвая цель должна собираться за 5 периодов
разумной игры, а закрыть потребности после дня ошибки — стоить больше обычного,
но укладываться в кошелёк. Всё это проверяет `EconomySimulationTest` на
настоящих файлах: поменял числа — запусти юнит-тесты.

## pets.json — внешность питомца

Три списка: тела, окрасы, аксессуары. Внешность — это их сочетание.

**Минимум по ТЗ 2.6 — не менее 9 визуально различимых комбинаций.**
Комбинаций получается `тела × окрасы × (аксессуары + 1)`; плюс один, потому что
вариант «без аксессуара» приложение добавляет само. Стадии роста за варианты
не считаются — это подтвердил ментор.

Наш случай: 1 тело × 5 окрасов × (2 аксессуара + без) → 15, и даже без
варианта «без аксессуара» — 10.

**Сова рисуется кодом (AD-1)**, картинок нет. Окрас — это четыре цвета вида
`#RRGGBB`: тело, крылья, лицо и обводка.

```
{ "id": "ginger", "titleKey": "pet.color.ginger", "body": "#EC9447", "wing": "#C46B2C", "face": "#FFE2BF", "ring": "#A4561F" }
```

Новый окрас — запись в `colors` и название в `explanations.json`, без правки
кода. Эталон цветов и формы — `docs/prototypes/owl.html`.

У дымчатого окраса `id` — `black`: так он назывался раньше, и сохранённые
профили хранят этот `id`. Менять `id` окраса нельзя — питомец сменит цвет.

Аксессуары рисуются кодом, поэтому в `accessories` работают только `scarf` и
`glasses`. Аксессуар с другим `id` приложение примет, но сова будет без него.
Головные уборы не берём: у совы перьевые «ушки».

Проверка цветов — тест `PetColorsTest`: он падает на цвете не в формате
`#RRGGBB` и называет окрас.

## shop.json — товары

**Минимум по ТЗ 2.6 — не менее 8 позиций, оба типа обязательно.**

| Поле | Что это |
|---|---|
| `icon` | картинка товара — один эмодзи, например `"🥣"`. Для TalkBack читается название, а не эмодзи |
| `price` | цена в монетах, больше нуля |
| `category` | `MANDATORY` — обязательный расход, `OPTIONAL` — желаемый |
| `effects` | как покупка влияет на питомца, список |

В `effects` каждый пункт — это `stat` и `delta`:

- `stat`: `MOOD` (настроение), `SATIETY` (сытость), `CARE` (уход)
- `delta`: на сколько меняется, от −100 до 100, но **не ноль**

Смысл разделения: `MANDATORY` — то, без чего питомцу плохо (еда, уход).
`OPTIONAL` — то, что радует, но без чего можно обойтись (игрушки, украшения).
Отказ от необязательной покупки по ТЗ прямо назван нормой, а не ошибкой.

## goals.json — цели накопления

**Минимум по ТЗ 2.6 — не менее 3 целей.**

Цель — предмет или событие с понятной ребёнку ценой. `price` больше нуля.
`icon` — картинка цели, один эмодзи, как у товаров.
Хорошо, когда цели разной стоимости: одна близкая, одна средняя, одна дальняя.

## tasks.json — задания

**Минимум по ТЗ 2.6 — не менее 6 заданий, по трём темам.** Разборы ошибок
(задания с `showWhen`, см. ниже) в минимум не входят.

`topic` — одно из трёх, и все три должны быть представлены:

- `PLANNING` — планирование бюджета
- `SAVING` — формирование сбережений
- `PAYMENTS` — платежи и покупки

**Задание — это игровая ситуация с выбором и последствиями**, а не тест с
вариантами ответа. Так прямо сказано в ТЗ 2.5.8.

`titleKey` — заголовок задания, он же вступление на экране прохождения.

### Шаги

**`CHOICE` — выбор из вариантов.** Нужно не менее двух вариантов.

```
{
  "type": "CHOICE",
  "promptKey": "task.my_task.step1",
  "options": [
    { "id": "buy_now", "textKey": "task.my_task.opt_buy" },
    { "id": "wait", "textKey": "task.my_task.opt_wait" }
  ]
}
```

**`THREE_JARS` — разложить сумму по трём банкам.** Подписи и порядок банок
задаёт задание: где-то разговор про «нужное и желания», где-то про копилку.
Идентификатор банки — это направление расхода, их ровно три:
`mandatory`, `wants`, `savings`.

```
{
  "type": "THREE_JARS",
  "promptKey": "task.my_task.step1",
  "totalCoins": 40,
  "jars": [
    { "id": "mandatory", "labelKey": "task.jar.mandatory" },
    { "id": "wants", "labelKey": "task.jar.wants" },
    { "id": "savings", "labelKey": "task.jar.savings" }
  ]
}
```

**`SHELF` — собрать корзину на прилавке задания.** Товары описаны прямо
здесь: тетради и сок в магазине питомца не продаются. `isMandatory` — то,
без чего набор не собрать; необязательное поле, по умолчанию `false`.

```
{
  "type": "SHELF",
  "promptKey": "task.my_task.step1",
  "budget": 35,
  "items": [
    { "id": "notebook", "titleKey": "task.item.notebook", "price": 10, "isMandatory": true },
    { "id": "keychain", "titleKey": "task.item.keychain", "price": 15 }
  ]
}
```

**`DISTRIBUTE` — то же распределение, что и `THREE_JARS`, но с общими
названиями направлений.**

```
{ "type": "DISTRIBUTE", "promptKey": "task.my_task.step1", "budget": 40 }
```

**`PICK_ITEMS` — корзина из товаров магазина.** `itemIds` берутся из `shop.json`.

```
{
  "type": "PICK_ITEMS",
  "promptKey": "task.my_task.step1",
  "itemIds": ["food-porridge", "toy-ball"],
  "budget": 30
}
```

### Разбор ошибки

Задание с полем `showWhen` — разбор ошибки. Оно не видно в списке заданий и
не входит в счётчики: оно само становится заданием дня, пока сова грустит из-за
названного показателя (ниже `sadThreshold` из `balance.json`), и остаётся им до
вечера, если ребёнок уже ответил на него сегодня.

```
"showWhen": { "type": "PET_SAD", "stat": "SATIETY" }
```

`type` пока один — `PET_SAD`; `stat` — `SATIETY` или `CARE`.

### Исходы

**У каждого задания не меньше двух исходов, и ровно один из них — `OTHERWISE`.**
`OTHERWISE` срабатывает, когда не подошёл ни один другой. Без него задание не
загрузится.

`condition` бывает таких видов:

| Вид | Когда срабатывает |
|---|---|
| `{"type": "SELECTED_OPTION", "optionId": "wait"}` | ребёнок выбрал этот вариант |
| `{"type": "SELECTED_OPTION", "optionIds": ["wait", "pause"]}` | выбрал любой из перечисленных |
| `{"type": "JARS_DISTRIBUTION", "minMandatory": 15, "minSavings": 5}` | в каждой названной банке не меньше указанного |
| `{"type": "BASKET_CONTAINS", "itemId": "juice_big"}` | взял этот товар |
| `{"type": "BASKET_CONTAINS_ALL", "requiredItemIds": ["notebook", "pens"]}` | взял все перечисленные |
| `{"type": "SAVED_AT_LEAST", "amount": 10}` | отложил не меньше указанного |
| `{"type": "SPENT_AT_MOST", "amount": 30}` | потратил не больше указанного |
| `{"type": "OTHERWISE"}` | во всех остальных случаях |

В `JARS_DISTRIBUTION` можно назвать любые банки: `minMandatory`, `minWants`,
`minSavings`. Про неназванную банку условие ничего не проверяет.

**`"correct": true` — верный ответ.** Монеты и отметка «пройдено» — только за
верный исход и только с первой попытки задания в этот день; повтор — тренировка
без монет. Не указано — исход неверный. У каждого задания должен быть хотя бы
один верный исход, иначе задание не загрузится.

`id` исхода необязателен: без него исход зовётся по месту в списке.
`reward` — награда в монетах, можно `0`; не указана — берётся `taskReward` из
`balance.json`. `effects` — как у товаров, необязательное поле.

**Монеты — не за каждое прохождение.** В день оплачивается столько заданий,
сколько задано в `rewardedTasksPerPeriod` (сейчас одно); остальные ребёнок
проходит ради объяснения и питомца, и приложение предупреждает об этом до
старта. Поэтому в тексте исхода **не пиши сумму словами** («ты получаешь
пятнадцать монет») — подставляй `{reward}`, а лучше вообще не упоминай монеты:
награду экран показывает отдельной строкой, и при повторном прохождении там
будет «сегодня без монет».

**Объяснение обязательно у каждого исхода, включая неудачный.** ТЗ 2.5.8 требует
короткое объяснение независимо от правильности решения, а ТЗ 2.5.9 — чтобы
неудачный исход объяснял последствие и подсказывал, как поправить.

## glossary.json — словарь терминов

Справочный раздел из ТЗ 2.5.11. Термин — это `titleKey` (само слово) и
`bodyKey` (объяснение в одну-две короткие фразы).

Кандидаты: бюджет, план, накопления, цель, обязательные расходы, желаемое.

## explanations.json — тексты

Плоский список: ключ и текст. Сюда идут **все** `...Key` из остальных файлов
плюс системные ключи, которые приложение показывает само.

Системные ключи уже перечислены в файле — их набор фиксированный, он приходит
из кода, добавлять и удалять их нельзя. Тексты в них менять нужно.

**Подстановки.** Фигурные скобки заменяются числами на лету:

| Ключ | Что подставляется |
|---|---|
| `purchase.done` | `{price}`, `{balance}` |
| `purchase.rejected` | `{shortfall}`, `{price}` |
| `balance.credited` | `{amount}`, `{source}` |
| `savings.deposited`, `savings.goal_reached`, `savings.withdrawn` | `{amount}`, `{saved}`, `{remaining}` |
| `growth.points_added`, `growth.stage_up` | `{earned}`, `{points}` |
| исходы заданий | `{reward}`, `{balance}` |

Ключи `recovery.*` — это подписи на кнопках, которые приложение предлагает,
когда денег не хватило. Их пять, набор тоже фиксированный.

Ключи `adult.about.1` … `adult.about.4` — исключение из правила выше: это
единственные тексты, которые читает не ребёнок, а взрослый, и их набор не
фиксирован. Каждый — одно предложение о том, чему игра учит. Пропущенный ключ
не ломает экран: строки просто не будет. Больше четырёх приложение не покажет.

## Требования к текстам

Всё это напрямую из ТЗ, раздел 3.6 и 2.2:

- Возраст читателя — 7–11 лет. Короткие фразы, простые слова.
- Сложный термин либо не используется, либо тут же объясняется.
- **Не пугать, не стыдить.** Питомец не болеет и не умирает от ошибок ребёнка.
  Неудача — это временная задача, а не наказание.
- Ошибка объясняется вместе со способом её исправить.
- Никаких упоминаний реальных денег, банков, брендов и финансовых продуктов.
