# Архитектурные решения

Решения, по которым идёт доработка v3 (`docs/PLAN_V3.md`). Код пишется
по ним; отступить от решения можно только после «ок» владельца проекта,
и тогда здесь меняется запись, а не только код.

Новое решение добавляется в конец со следующим номером: что решили,
почему и что сломается без этого.

## AD-1. Сова рисуется кодом на `Canvas`, а не картинками

Эмоции видны на морде, стиль одинаков на всех стадиях, окрас задаётся
цветами в `pets.json`, сборка меньше примерно на 11 МБ. Картинки из
Nano Banana остаются для иконки, карточки RuStore и презентации.
Эталон геометрии и цветов — `docs/prototypes/owl.js`.

## AD-2. Потребности считаются из показателей совы, ночь — при закрытии игрового дня

Никакого реального времени: демо проходит пять дней подряд, а ребёнок
не получает «голодного» питомца после выходных.

## AD-3. Рост: в голодный день очков нет, иначе три условия по 2 очка

Сова не может вырасти, если её не кормят (замечание 13), а прогресс
не отнимается (ТЗ 2.2). «Нужное выполнено» больше не зависит от того,
сколько потрачено относительно плана.

## AD-4. Желаемое ограничено остатком по плану, нужное не блокируется

Забота о питомце не должна зависеть от плана (ТЗ 3.5), а необязательная
покупка переносится без наказания (термины ТЗ).

## AD-5. Доля копилки переводится при подтверждении плана одной записью

Через существующие `SavingsEngine` и `OutcomeRecorder`. Без общей записи
сбой между подтверждением и переводом оставил бы план подтверждённым,
а копилку пустой.

## AD-6. «Первая попытка задания за день» — по времени операции дохода дня

Схема базы не меняется, а в демо-режиме, где дни проходят за секунды,
правило работает так же. Оба времени берутся от одних часов.

## AD-7. Разбор ошибки — обычное задание из `tasks.json` с условием показа

Условие проверяется по текущим показателям совы; открытый разбор остаётся
заданием дня до вечера. Разбор не показывается в списке заданий и не
входит в счётчики и минимум ТЗ 2.6. Новый разбор добавляется без правки
кода (ТЗ 2.5.14).

## AD-8. Настройка движения передаётся всем экранам через `CompositionLocal`

Из существующей `ANIMATIONS_ENABLED`. Один источник правды для переходов,
полосок и прыжка совы.

## AD-9. Схема базы данных в v3 не меняется

Новый тип операции «покупка цели» хранится как значение существующего
поля; желание «Хочу завтра» — в настройках профиля.

## AD-10. Покупка цели обнуляет копилку по цели и не меняет кошелёк

Коллекция вещей рядом с совой строится по этим операциям, отдельной
таблицы нет.

## AD-11. Картинки товаров и целей — эмодзи в контенте

Без библиотек и файлов; новый товар с картинкой — правка JSON.

## AD-12. Инструментальные тесты компилируются на каждый коммит

Иначе сломанные тесты экранов остановят и тесты базы, которые лежат рядом.
